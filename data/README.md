# data

Every non-code input of the repository.

| Path | What |
|------|------|
| `model/` | The component model and the generators' inputs: `components.json` (creator docs), `mappings.json`, `coverage.md`, `bds-feedback.json`, `transforms.json`, `fixtures.json`, `api.json`, `ATTRIBUTION.md`; `constants-history.json` (vanilla constants) |
| `bds/<bds version>/` | What one BDS build gave: `addon/` (capture of the capture add-on), `vanilla/`, `creative-*/` (captures of the creative probes), `spec/` (capture of the spec add-on, input of `infer`), `dump.json.gz` (Script API dump, the baseline of `update`), `experiments.json`, `behaviour-probe/` (what `behaviour-probe` measured: `probe.log`, the console it was measured from, and `capture.json`) |
| `bds/WIRE-NOTES.md`, `bds/CREATIVE-ORDER.md` | What BDS sends, and how it orders custom content in the creative inventory |
| `addons/` | The packs run on BDS: `capture` (every component; generated by `addon --kind capture`, plus the committed `content-log.txt`), `creative` (generated by `addon --kind creative`), `dump` (hand-written Script API dump pack), `probe` (hand-written behaviour probe: blocks, a body entity and the script that measures what BDS does; run by `behaviour-probe`) |

Every generated file says so: Java and text files by a `// Generated by ...` or `#` header, JSON by a first key `_generated`
(readers ignore it), bundled `.nbt` by a root string `_generated`, packs by their manifest description. The marker names the
command that writes the file. Generated: `addons/capture` and `addons/creative` (never edit; `FixedAddonsTest` checks them;
their `content-log.txt` is captured from BDS), `model/components.json`, `model/mappings.json`, `model/coverage.md`,
`model/bds-feedback.json`, `model/constants-history.json`, `paletter/api/paletter.api`, the bundled data of
`paletter/src/main/resources/paletter` (`*.nbt`, `versions.txt`) and `paletter/src/generated`. Hand-written inputs, never
marked: `api.json`, `fixtures.json`, `transforms.json`, `renames.txt`. Captured from BDS: everything under
`bds/<build>/`, by the tool in the table below. `GeneratedMarkersTest` checks all of this.

Unexplained captures fail `update` and CI but not `./gradlew build`: `./gradlew :tools:run --args="check-mappings --strict"` fails on residual bits no field or format sweep explains and on captured wire paths that are neither in `mappings.json` nor classified by `WireShapes.classify`, and prints what and where.

## Captured from BDS

Everything under `bds/<build>/` was captured from the Bedrock Dedicated Server build named by the directory (for example
`1.26.63.1`), by a tool of this repository. None of it is written by hand and none of it is edited: a capture is replaced by
running the command again (usually through `update`). The binary captures (`.nbt`, `.gz`) carry no marker of their own, so
this section is their marker; the JSON captures also name their build in `bdsVersion`.

| Path in `bds/<build>/` | Captured from BDS by |
|------------------------|----------------------|
| `dump.json.gz` | `./gradlew :tools:run --args="bds-run ..."` (the Script API dump pack `addons/dump`), baseline of `update` |
| `experiments.json` | `update` (experiment discovery on BDS) |
| `education.json` | `education-capture` |
| `vanilla/` | `capture` (the headless client against vanilla BDS; `compare-*.txt` is the output of `compare`) |
| `addon/` | `capture` against BDS with the generated pack `addons/capture` |
| `creative-probe/`, `creative-probe-file-order/`, `creative-large/` | `creative-probe` / `capture` with the generated packs `addons/creative` and `addon --kind creative-large` |
| `spec/` | `spec-capture` (the spec add-on generated from `model`, run on BDS); input of `infer` |
| `spec-keys/` | `spec-capture --probe-keys` (variants with keys the docs do not list; its result is `model/bds-keys.json`; not read by `infer`) |
| `spec-format/` | `spec-capture --format-sweep` (components at the format versions around their boundaries; `format-sweep.json` is the report; not read by `infer`) |
| `behaviour-probe/` | `behaviour-probe` (the probe add-on `addons/probe`: friction, explosion resistance, light, collision and fire of custom blocks and the collision of doors, measured by experiment; `probe.log` is the console it was measured from); input of `behaviour import` |
